# Architecture

## App Shape

- `package.json`'s `name` field defines the desktop app package as `bppinstaller`, and its `scripts` map exposes the development, build, test, type-check, verification, and Tauri entry points; its `version` field is the single version source (see version sync below).
- The frontend is built by Vite from `src/`; `build.beforeDevCommand` and `build.beforeBuildCommand` in `src-tauri/tauri.conf.json` invoke `npm run dev` for development and `npm run build` before bundle creation. The `scripts.build` chain in `package.json` (`build` → `build:after-bindings`) generates bindings, runs the prebuild source/resource checks and TypeScript check, then builds the frontend via `scripts.build:frontend`.
- The main desktop shell is Rust/Tauri. The `run()` function in `src-tauri/src/lib.rs` registers native plugins (window-state, single-instance, updater, process, dialog, opener) and shared state (`SelectedGameInstallationState`, `StreamRuntime`, `InstallerContextState`, `TrayMenuState`), attaches the canonical Specta builder's invoke handler, builds the generated Tauri context, and runs the app with a platform event callback for macOS `Reopen`.
- The default main window is resizable and maximizable at 1020 x 680 with a 900 x 600 minimum, set via `app.windows` in `src-tauri/tauri.conf.json`. Windows overrides it with a resizable 972 x 612 frameless, shadowless window with the same minimum that starts hidden, via `app.windows` in `src-tauri/tauri.windows.conf.json`; disabling the undecorated native shadow also removes its one-pixel system border, while Tauri's undecorated resize handler keeps edge resizing available. The `setup()` closure's Windows block in `src-tauri/src/lib.rs` shows the window and actively re-enforces the minimum size on native resize events through `main_window::enforce_minimum_size` (`src-tauri/src/main_window.rs`).

## Native Runtime

- Tauri startup builds the tray, warms `InstallerContextState`, and asks `StreamRuntime` to ensure the stream service — all inside the `setup()` closure in `src-tauri/src/lib.rs`, which calls `build_tray` (`src-tauri/src/tray.rs`), spawns a blocking task that calls `InstallerContextState::get_or_initialize` (`src-tauri/src/services/startup.rs`), and spawns an async task that calls `StreamRuntime::ensure` (`src-tauri/src/stream/runtime.rs`). Install detection waits on the same `OnceLock`-backed initializer — `detect_for_install` in `src-tauri/src/services/detect/mod.rs` also calls `InstallerContextState::get_or_initialize` — so no frontend event/refetch race is required.
- Main-window restoration is the single `main_window::restore` function (`src-tauri/src/main_window.rs`): it attempts show, unminimize, and focus independently, logging a failed step while continuing. Tray clicks/menu actions call `show_main_window`, which calls it (`src-tauri/src/tray.rs`); single-instance activation calls it directly from the `tauri_plugin_single_instance::init` closure; and every macOS `RunEvent::Reopen` calls it from the `app.run` callback without a visible-window condition (both in the `run()` function in `src-tauri/src/lib.rs`).
- Window-state persistence is restricted to size, position, and maximized state; visibility, fullscreen, and decorations are neither saved nor restored — the `tauri_plugin_window_state::Builder` registered in `run()` only enables `StateFlags::SIZE | StateFlags::POSITION | StateFlags::MAXIMIZED` (`src-tauri/src/lib.rs`).
- Close behavior is service-aware: the `on_window_event` closure attached in `run()` prevents the main window's close request and hides it instead while `StreamRuntime::snapshot().running` is true (`src-tauri/src/lib.rs`).
- The default capability grants window minimize/toggle-maximize/close/show/drag, updater check/download/install, process restart, `steam://*` opening, and dialog permissions via the `permissions` list in `src-tauri/capabilities/default.json`.
- The selected game installation is process-wide, session-scoped state shared by Install, History, and Stream. `SelectedGameInstallationState::resolve` in `src-tauri/src/services/selected_game_installation.rs` (delegating to `resolve_game_path_core` in `src-tauri/src/services/game_path.rs`) resolves it with explicit-path, then session-selected, then startup-detected, then fallback priority. The state lives only in the `SelectedGameInstallationState` Tauri manages in `run()` (`src-tauri/src/lib.rs`) and is recreated empty on every app restart.

## Feature Boundaries

- Install: Rust's `install` module (`src-tauri/src/services/install/operation.rs`, `src-tauri/src/services/install/mod.rs`) owns detection, planning, and effects behind `InstallState`; the frontend's `createInstallWorkflow` (`src/features/install/installWorkflow.ts`) owns UI-only single-flight and confirmation state. Detail: `docs/truth/install-reset.md`.
- History: the `History` facade (`src-tauri/src/services/history.rs`) is the sole owner of storage-path derivation, reads, and cleanup; Tauri commands carry only ids and cleanup scope/preset, never raw paths. Detail: `docs/truth/history-stream.md`.
- Stream: `StreamRuntime` (`src-tauri/src/stream/runtime.rs`) is the only lifecycle-mutation boundary for the local overlay HTTP service; the frontend's `createStreamWorkflow` (`src/features/stream/streamWorkflow.ts`) owns UI capability state layered on top of it. Its `currentLocale` port is a live read rather than a captured value, so opening the calibration page in the current language never restarts the workflow. Detail: `docs/truth/history-stream.md`.
- Updater: `createUpdaterMachine` (`src/features/about/updater.ts`) owns the phase/progress/problem snapshot; `getUpdaterUiContract` (`src/features/about/updaterPresentation.ts`) derives modal metadata from it. Detail: `docs/truth/updater-release.md`.
- About bootstrap: `createAppBootstrapMachine` (`src/features/about/appBootstrap.ts`) owns the loading/fallback/authoritative-data snapshot, kept separate from the updater's own snapshot. Detail: `docs/truth/frontend.md`.
- Cross-cutting frontend primitives: `src/features/shared/confirmedOperation.ts` owns destructive-confirmation state and `src/features/shared/modalCoordinator.ts` owns modal-queue state, shared by Install, History, and the update modal rather than reimplemented per feature. Detail: `docs/truth/frontend.md`.
- All Install/History/Stream command failures cross IPC as the same `SemanticProblem` type (`src-tauri/src/problem.rs`); each service classifies its own stable `SemanticProblemCode` values into it.

## Build And Generated Artifacts

- `scripts.check` in `package.json` generates TypeScript bindings and runs `tsc --noEmit`; `scripts.test` generates bindings with their Rust export tests, checks binding freshness, and runs Vitest, while `scripts.test:rust` is the full locked Rust test entry point.
- The Tauri IPC schema is authored in Rust command signatures and collected once by `builder()` in `src-tauri/src/commands/registry.rs`, whose `collect_commands!` list is exported to TypeScript by the `export_bindings` test in the same file; the same builder is constructed as `command_builder` in the `run()` function in `src-tauri/src/lib.rs`, which supplies the production invoke handler via `command_builder.invoke_handler()`.
- Specta is the only direct TypeScript binding stack: the `specta`, `specta-typescript`, and `tauri-specta` dependency pins in `src-tauri/Cargo.toml` are exact-pinned, with no `ts-rs` dependency or fallback generator.
- `npm run generate:bindings` runs `runGenerateBindings` in `scripts/generate-bindings.mjs`, which exports to a temporary directory, then `commitGeneratedBindings` validates and normalizes `commands.ts` and atomically replaces `src/types/generated/` via `replaceDirectoryWithBackup`; that replacement restores a captured backup and never removes the prior target when the backup rename itself fails.
- Version sync treats `package.json`'s `version` as the source: `synchronizeVersions` in `scripts/version-sync.mjs` writes package-lock.json (both root `version` fields), Tauri config, Cargo.toml, and Cargo.lock versions. `npm run prebuild-check` fails on any misalignment because `runPrebuildCheck` in `scripts/prebuild-check.mjs` calls `collectVersionSnapshot` and `assertVersionsAreAligned` (both in `scripts/version-sync.mjs`).
- `runPrebuildCheck` in `scripts/prebuild-check.mjs` also verifies platform ZIP payloads (`validatePayloadZip`) and the macOS trampoline stub (`assertMacosTrampolineStub`) when applicable.
- Tauri updater artifacts are enabled via `bundle.createUpdaterArtifacts` in `src-tauri/tauri.conf.json`.
- The Rust toolchain is pinned via `toolchain.channel` = 1.97.0 (`toolchain.profile` = minimal, with `toolchain.components` = clippy and rustfmt) in `rust-toolchain.toml`; rustup selects it automatically for all `cargo`/Tauri builds.
