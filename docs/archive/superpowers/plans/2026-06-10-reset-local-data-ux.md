# Reset Local Data UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make "重置本地数据 / Reset Local Data" behave like an explicit destructive data action: confirm before deletion, explain exactly what is deleted, disable the action when no local data exists, distinguish deletion from no-op, and expose useful partial-failure details.

**Architecture:** Keep backend deletion ownership in Rust and keep frontend copy/state ownership in React. Extend the install state contract with `has_resettable_data`, return a typed reset result from `reset_bpp_data`, then route the frontend through a dedicated confirmation modal and a small partial-failure details component.

**Tech Stack:** Tauri command bridge, Rust services with `ts-rs` bindings, React 19, TypeScript, lucide-react, existing `Dialog` component, existing i18n catalog.

- Only uninstall is styled as dangerous in the same button group: `src/features/install/InstallActionsPanel.tsx:99-105`.
- The install/reinstall flow already uses a modal confirmation pattern mounted from the page: `src/pages/Install.tsx:49-59`, `src/features/install/InstallConfirmModal.tsx:31-141`.
- `resetData` currently calls the backend immediately and always shows `resetDataDone` on success: `src/features/install/useInstallPage.ts:176-189`.
- The current success copy is generic: `src/i18n/messages.ts:87` and `src/i18n/messages.ts:281`.
- The backend reset flow stops the stream server first, validates the game path, checks whether The Bazaar is running, and then deletes the BPP data directory: `src-tauri/src/services/bepinex/mod.rs:25-55`.
- The data directory name is `BazaarPlusPlusV4`: `src-tauri/src/config.rs:1`.
- The database, screenshots, and combat replay videos live under the BPP data directory: `src-tauri/src/services/paths.rs:15-24`.
- Missing data directory is currently a successful no-op: `src-tauri/src/services/bepinex/payload.rs:497-503`.
- `can_reset_data` is currently derived only from a valid launchable game path, not from whether resettable data exists: `src-tauri/src/services/install/mod.rs:229` and `src-tauri/src/services/install/mod.rs:288-293`.
- Partial failures carry failed paths in a stable machine-code payload: `src-tauri/src/services/bepinex/mod.rs:58-66`, but the UI reduces that to a count: `src/features/install/useInstallPage.ts:267-270`.
- Generated frontend types come from `scripts/generate-bindings.mjs`, which runs `cargo test export_bindings` and writes `src/types/generated/bindings`: `scripts/generate-bindings.mjs:64-83`.

## Desired User Flow

1. User sees the reset action as a destructive local-data action, not as "repair".
2. If the selected game path is valid but `BazaarPlusPlusV4` does not exist, the reset action is disabled and labeled "暂无本地数据".
3. If data exists, clicking the reset action opens a confirmation modal.
4. The confirmation modal states:
   - The action deletes local BazaarPlusPlus data under `BazaarPlusPlusV4`.
   - The deleted data includes the local database, screenshots, and combat replay videos.
   - The action does not uninstall The Bazaar or the BazaarPlusPlus mod.
   - The Bazaar must be closed before reset.
5. Confirming runs `reset_bpp_data`.
6. If data was deleted, the status message says "本地数据已删除".
7. If the backend reports no data was present, the status message says "未找到可重置的本地数据".
8. If the game is running, the existing localized game-running error remains.
9. If deletion partially fails, the main error stays concise and a details entry lists the failed paths and offers copying diagnostic text.

- [ ] **Step 2: Make the reset backend return whether data existed**

In `src-tauri/src/services/bepinex/mod.rs`, change the public reset functions from `Result<(), String>` to `Result<bool, String>`. Use the existing `BAZAAR_DATA_DIRECTORY` constant to detect whether the reset is a deletion or no-op before cleanup:

```rust
pub async fn reset_bpp_data(
    stream_state: tauri::State<'_, StreamRuntimeState>,
    game_path: String,
) -> Result<bool, String> {
    // Drop our own SQLite connections before touching the data directory.
    // Without this, OBS overlay polling keeps `bazaarplusplus.db` open and
    // Windows refuses to delete it (the headline customer complaint).
    let _ = crate::stream::server::stop(stream_state.inner()).await;

    tauri::async_runtime::spawn_blocking(move || reset_bpp_data_blocking(Path::new(&game_path)))
        .await
        .map_err(|err| format!("failed to reset BazaarPlusPlus data: {err}"))?
}

fn reset_bpp_data_blocking(game_path: &Path) -> Result<bool, String> {
    payload::ensure_valid_game_path(game_path)?;

    if crate::services::game_process::is_bazaar_running_best_effort() {
        return Err(RESET_BPP_DATA_ERR_GAME_RUNNING.to_string());
    }

    let data_dir = game_path.join(crate::config::BAZAAR_DATA_DIRECTORY);
    let had_resettable_data = data_dir.exists();
    let report = payload::cleanup_bpp_data_directory(game_path);
    if !report.is_empty() {
        return Err(format_partial_failure(&report.failed));
    }

    debug_log!(
        "Reset BazaarPlusPlus data directory at {}",
        game_path.display()
    );
    Ok(had_resettable_data)
}
```

```ts
const resetData = useCallback(
  () =>
    run(
      'resetData',
      async () => {
        if (!state.has_resettable_data) {
          setResetDataFailurePaths([]);
          setMessage(t('resetDataNothingToDelete'));
          return;
        }

        const path = requireGamePath(state, t);
        const result = await resetBppData(path);
        setState(result.state);
        setResetDataFailurePaths([]);
        setMessage(
          result.removed_data
            ? t('resetDataDone')
            : t('resetDataNothingToDelete')
        );
      },
      {
        onStart: () => {
          setMessage(null);
          setResetDataFailurePaths([]);
        },
        errorMessage: (caught) => formatResetBppDataError(caught, t, setResetDataFailurePaths)
      }
    ),
  [run, state, t]
);
```

Change the formatter signature so it can store detail paths:

```ts
function formatResetBppDataError(
  error: unknown,
  t: Translate,
  setFailurePaths: (paths: string[]) => void
) {
  const resetError = parseResetBppDataError(error);
  if (resetError?.code === 'game_running') {
    setFailurePaths([]);
    return t('resetDataBlockedByGame');
  }
  if (resetError?.code === 'partial_failure') {
    setFailurePaths(resetError.paths);
    return t('resetDataPartialFailure', {
      count: Math.max(1, resetError.paths.length)
    });
  }
  setFailurePaths([]);
  return toErrorMessage(error);
}
```

Create `src/features/install/ResetDataFailureDetails.tsx`:

```tsx
import { Clipboard, ListX } from 'lucide-react';
import { useState } from 'react';
import { useI18n } from '../../i18n/LocaleProvider';

export function ResetDataFailureDetails({ paths }: { paths: string[] }) {
  const { t } = useI18n();
  const [copied, setCopied] = useState(false);

  if (paths.length === 0) return null;

  const diagnosticText = [
    'BazaarPlusPlus reset local data partial failure:',
    ...paths.map((path) => `- ${path}`)
  ].join('\n');

  const copyDiagnostics = () => {
    void navigator.clipboard?.writeText(diagnosticText).then(() => {
      setCopied(true);
      window.setTimeout(() => setCopied(false), 1600);
    });
  };

  return (
    <details className="selectable rounded-sm border border-[rgba(190,80,80,0.2)] bg-[rgba(160,50,50,0.06)] px-3 py-2 text-xs text-[rgba(245,220,220,0.86)]">
      <summary className="cursor-default flex items-center gap-2">
        <ListX size={14} />
        {t('resetDataFailureDetails')}
      </summary>
      <div className="mt-3 flex flex-col gap-3">
        <ul className="m-0 max-h-32 overflow-auto pl-4 leading-relaxed">
          {paths.map((path) => (
            <li key={path} className="break-all">
              {path}
            </li>
          ))}
        </ul>
        <button
          type="button"
          onClick={copyDiagnostics}
          className="self-start inline-flex items-center gap-2 rounded-sm border border-[rgba(190,80,80,0.24)] bg-[rgba(160,50,50,0.08)] px-3 py-1.5 text-[rgba(245,220,220,0.9)] hover:bg-[rgba(160,50,50,0.14)] transition-colors"
        >
          <Clipboard size={13} />
          {copied ? t('resetDataFailureCopied') : t('resetDataFailureCopy')}
        </button>
      </div>
    </details>
  );
}
```
